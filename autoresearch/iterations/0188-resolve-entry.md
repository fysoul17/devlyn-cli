## Accepted policy delta

work is the default when inspection establishes tractable behavior, boundaries and
verification, including bounded multi-file changes. Full resolve is automatic only
for concrete interacting requirements or verification too complex to manage reliably
in the current context; name the interaction/gap. Coupled durable state, concurrent
ownership and failure recovery are examples, not substring triggers. Missing intent
or access calls for investigation/clarification first.

Direct work retains scope, pins, checks, diff review and delivery; consequential
changes require independent review. Explicit resolve/spec-mode requests and queue
drains keep the canonical workflow. A requirements document alone is not a workflow
invocation. Mid-edit escalation carries existing changes into scope/evidence.

skill body after frontmatter is byte-identical; phases, workers, validators, runtime

exception, runtime classifier, new flag, installer overwrite policy or npm release.

contract or a statistically established complexity threshold.

**No overengineering:** remove broad trigger obligations rather than build another
classifier. **No guesswork:** preserve limited historical claims and distinguish
routing comprehension from implemented task quality. Further deletion of the
concrete-gap requirement would lose the guard against replacing category triggers
with an unexplained subjective difficulty label.
