## Question and evidence

additional verified-completion cost? [0175](0175-routing-boundary.md) found equal
L/C quality with longer solo/pair times, and a real H precision repair on pair.
It did not isolate the base instructions or the OTHER reviewer. [0178](0178-valid-repair-comparison.md)
compared PLAN/IMPLEMENT wording on seeded repairs; 4/4 versus4/4 supplied no
promotion evidence. Neither result establishes that a short contract suffices.

The [candidate](../experiments/0179/AGENTS.candidate.md) is a research artifact,
not an installed AGENTS/CLAUDE replacement. It keeps the seven named principles
while testing different operating guidance. The wording concentrates on intent, evidence,
scope, failure behavior and actual verification/delivery. It removes phase
selection, mandatory worker structure, repeated prohibitions, skill catalog and
pipeline delivery-helper instructions from this experimental surface. This unit
does not change shipped routing, pins or delivery helpers; participants do not
load those surfaces.

Execution / Error Handling / Evidence Over Claim. The explicit-constraint miss

## Comparison contract

- A: native execution with no Devlyn instruction payload.
- B: identical native execution plus the exact candidate as project instructions.
- Use independent Git roots and process-local native configuration directories
  without personal AGENTS/CLAUDE, configuration, memory or plugins. A has no
  project instructions; B has only the candidate bytes in baseline AGENTS.md,
  committed before dispatch, preserved during the run and excluded from product
  scoring. That instruction file is the sole intentional input-tree difference.
  Both keep the same built-in native instructions and callable tools. Disable
  discovered external skill cards equally. This controlled single-agent screen
  is not a native-best comparison with every extension enabled.
- Keep model/version/effort, source, request, tools, permissions, dependencies,
  resource limits and scoring identical. Preserve native system instructions.
  Do not add candidate-equivalent process instructions to the shared task prompt.
- Draws are unattended. Fully specify tasks before dispatch; an unanswered
  clarification or concrete blocker leaves the draw incomplete, with no hidden
  operator answer or reroll. The shared request sets the delivery endpoint:
  in-tree implementation, verification and final response, without commits,
  publication, queue or archive work. A task requiring another endpoint must
  state it identically for both arms before freeze.
- Initially compare A/B only. B plus independent review/repair is a separate
  later comparison. Do not launch solo/pair resolve arms under the owner's ban.
- Use fresh development cases with a small regression control and a harder
  multi-module compatibility or persistence/failure task. Before dispatch, prove
  requirements are satisfiable, calibrate positive/negative implementations and
  ensure the checker does not reject valid alternative solutions. Never alter
  the domain after observing participant output to manufacture success.
- Freeze exact task bytes, candidate, launch configuration, oracle, scope,
  budgets, balanced run order and at least two fresh draws per arm per case.
  Task selection and calibration are still pending; no draws are authorized by
  this document alone without completing those concrete admission checks.
- Primary product success is independently checked explicit requirements,
  existing behavior/tests and frozen scope. Score participant-authored tests or
  verification separately unless the common task explicitly requires them;
  counts and process compliance earn no product-quality credit. Native exit0 is insufficient. Keep
  requirement misses and infrastructure failures visible, with no rerolls or
  silent model substitution.
- Measure correctness/completeness first, then time through in-session repair and final
  verification, then observed tokens/cost. Report preparation and independent
  assessment time separately; unavailable telemetry is UNKNOWN.
- Blind source reviewers to arm, model, timing and other judgments. Root sees
  launch labels and cannot claim blindness; adjudicate from frozen code and
  counterexamples. Compare completion times within matched successful products,
  while retaining failures and consumed time in the complete result table.
- Prediction to test: B improves complete-task success over A without a paired
  regression. A tie or regression supplies no quality-lift evidence. Positive
  development results justify disjoint repeated confirmation, not deployment.
  Equal observed success is not statistical equivalence. Historical0175 times
  are context only, never a matched control for new A/B draws. With no current
  installed-contract arm, A/B cannot establish that B replaces that contract.
