I fixed `--limit 0` so it now returns `0`, and an omitted `--limit` still returns `10`. The public check (`python3 -B -m pytest -q`) passes with 7 tests. Following the repo's delivery policy, the change went out as PR #1, which is merged, and local `main` is now at that merged commit.

**What I changed**
- **`src/limitcli/__init__.py`:** the default was applied with `return args.limit or 10`, which replaces any falsy value, including an explicit `0`. The parser now supplies the default (`default=10`) and the function returns `args.limit` as is. I removed the `args.limit is not None` check because the value can no longer be `None`.
- **`tests/test_regression.py` (new):** one test checks that `--limit 0` returns `0`. A second checks that `--limit` with no value and an unknown flag both exit with code 2. Those two error cases weren't covered by the existing tests.

**What I verified**
- Before the fix, `--limit 0` and `--limit=0` both returned `10`.
