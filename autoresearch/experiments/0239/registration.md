## Prediction, evidence and stopping

Prediction: if the owner chooses a child whose result is needed for completion,
reading C before launch/final changes lifetime management so the result is
received and the request delivered within the owner's running task. Record
guide-read timing, the stated dependency, actual launch/wait mode, child outcome,
owner continuation, any witness/fix and final delivery independently of scores.
Starting or merely receiving a child is not evidence of useful reasoning.

After the one ordinary pair, close C without adoption if any of these holds:

- C does not exercise the needed child behavior; do not reroll for activation.
- Both arms already finish needed children and consume their results safely.
- C ends while a required child is pending, uses an invented wait interface,
  loses source correctness or delivery, or changes sealed inputs.
- No native evidence connects C's read to a useful lifetime difference.
- Claimed benefit rests on a hidden requirement, invalid evaluator, omitted
  child costs, or an unexplained setup/accounting difference.

A continuation signal requires C to deliver correct source and consume its
required child's terminal result before final, while B loses a needed result
or delivery through the observed lifetime mechanism. A different launch flag
with equally safe outcomes, mere delegation avoidance, or a faster singleton
without the lifecycle difference is not such a signal. Source-only differences
are reported but cannot establish this mechanism. An independently witnessed
source regression blocks continuation even if the current oracle misses it.

A signal licenses designing the next Codex comparison and independent
confirmation/easy-orphan controls; it does not adopt C or automatically dispatch
more cells. Register their rules and exact inputs separately before those calls.
Without a signal, best solo stays B and subsequent residual pair work uses B.
Do not add another completion slogan to rescue this candidate.

Charge complete owner/child/retry/failure input (including caches), output
(including reasoning) and wall time. Missing usage is UNKNOWN; zero correct
deliveries has no finite per-success cost. Do not subtract environment recovery
or child waits from raw usage. A completion correction, any measured cost tradeoff
and unproven general bare-model benefit must be reported separately. No cost,
token or call budget is introduced; this is a fixed diagnostic sequence with
existing watchdogs, not a resource cutoff.
