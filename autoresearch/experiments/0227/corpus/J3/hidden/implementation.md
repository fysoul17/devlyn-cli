# J3 implementation instructions

This is an authoring design for the isolated implementer, not a patch. The repository is `repos/node-lru-cache`; implement against its pinned checkout. Produce a reference and one defective twin with exactly these changed paths: `src/index.ts` and the new `test/memo-failure.ts`. The test file is byte-for-byte identical in both variants. Do not change `test/memo.ts`, snapshots, manifests, lockfiles, generated distribution files, or configuration.

## Existing behavior and reference design

At this revision, `#memo` destructures `context`, `status`, and `forceRefresh` away from the callback's `options`, then calls `#get` before deciding whether to call `memoMethod`. `#get` can move an entry to the MRU end, reset its TTL start, or delete an expired entry and invoke disposal hooks. A callback throw therefore leaves effects behind. The helper `#peek` already supplies the same prior-value selection for ordinary cached values and background-fetch stale values without those cache mutations.

Keep the change within `#memo` plus the two relevant API comment blocks:

1. Keep the missing-`memoMethod` error and outer `memo()` wrapper unchanged. Keep the existing extraction of `context`, `status`, `forceRefresh`, and mutable callback/set `options`.
2. Before invoking any memo callback, create a separate lookup-options object. Resolve `allowStale`, `updateAgeOnGet`, and `noDeleteOnStaleGet` with the same destructuring-default behavior as `#get`, including fallback when a supplied property is `undefined`. Copy the resolved primitive values, rather than holding the mutable callback options object. Do not include the outer `status` in this lookup object.
3. Capture the key's index and, if present, whether its stored value is a background fetch and a single `#isStale(index)` result. Read the candidate prior value with private `#peek(k, { allowStale: true })`, which does not sample staleness, then select `undefined` if the captured entry is stale and the resolved `allowStale` is false. Otherwise select that candidate. Do not call public `peek()`, which would add status/diagnostics effects. This lookup must not publish or add `peek` fields to the caller's status.
4. Compute refresh from `forceRefresh || priorValue === undefined`. Preserve `status.forceRefresh`, `status.memo`, and the existing hit/result reporting. For a non-refresh hit, apply the normal private-get effects directly using the captured index, background-fetch flag, and staleness decision, then return `priorValue`. A fresh hit moves the entry to the tail and calls `#updateItemAge(index)` if the resolved `updateAgeOnGet` is true. A stale ordinary hit calls `#delete(k, 'expire')` unless the resolved `noDeleteOnStaleGet` is true; a stale background-fetch hit does neither. Do not call `#get` or recheck staleness on this hit path: the single time observation that accepted the value also determines its lookup effects, even if the clock would cross expiry on another read. Normal age refresh may read the clock to set the new start; it must not reconsider freshness.
5. For a refresh, call `memoMethod` once with the nonmutating lookup's prior value, the mutable callback options, and context. Let throws propagate directly. Do not introduce catch-and-restore logic, snapshots, or new rollback machinery.
6. Only after `memoMethod` returns, call `#get(k, lookupOptions)` to apply the read effects. Ignore this commit lookup's return value. Then use the existing `status.value` assignment and `#set(k, result, options)` with the callback's possibly modified set options, and return the callback result.

This order preserves fresh-read age refresh even when `noUpdateTTL` prevents the following set from resetting TTL. For a stale entry and default deletion, success still disposes with reason `expire` before adding the replacement, so `noUpdateTTL` does not incorrectly carry the old entry's start into the new entry. With `noDeleteOnStaleGet: true`, successful replacement keeps the usual set semantics, including retaining the old TTL if `noUpdateTTL` is true. A stale value with `allowStale: true` and no forced refresh is a hit and keeps the existing get-like deletion behavior.

The callback can change its set options, so never freeze or replace that options object with the lookup snapshot. Snapshot only the three get fields. The outer memo status was intentionally absent from private get/set calls in the original code; keep that behavior. If a callback itself adds an `options.status`, preserve its ability to reach `#set`, but do not use it for the already-resolved lookup. Do not change context typing or successful outer status fields. On the refreshing path, time is read normally when the successful lookup effects commit; accepted hits reuse their selection's staleness decision as described above. Do not promise to rewind elapsed time or callback-owned mutations.

Update `MemoizerMemoOptions` documentation: callback changes to get options cannot affect this operation because they were resolved at entry, rather than because `get()` has already run. Update `memo()` documentation to describe the unchanged-cache guarantee on `memoMethod` throws and its callback-owned mutation boundary.

## Public regression file

Use Tap and the source import convention in `test/memo.ts`. All timed scenarios use `let now = 100`, `perf: { now: () => now }`, `ttlResolution: 0`, and no `ttlAutopurge`. Keep tests isolated from diagnostics subscriptions. Clear hook logs after setup `set()` calls. Hook logs record hook name, value, key, and reason; keep callback invocation records separate so tests do not demand the old ordering of the memo callback relative to successful disposal.

Implement these public cases, keeping every assertion shared by the reference and twin:

- **Compound failure, retry, and eviction.** Use `max: 2`, `maxSize: 20`, `sizeCalculation: value => value.length`, `ttl: 100`, and `updateAgeOnGet: false`, with `dispose`, `disposeAfter`, and `onInsert` logs. Seed `a = 'AA'`, then `b = 'BBB'` at time 100. At 125, force-refresh MRU key `b` with a callback that throws a unique sentinel. Assert exact thrown identity, entries `[['b','BBB'],['a','AA']]`, size 2, calculated size 5, remaining TTL 75 for each, unchanged per-entry start/duration/size, and no hook calls. Retry `b` successfully with the same context object identity observed by the callback; return `'BBBB'` and change callback options to `ttl: 40` and `noDisposeOnSet: true`. Assert prior value `'BBB'`, returned/stored `'BBBB'`, order `b,a`, calculated size 6, TTL 40 for `b`, and only `onInsert('BBBB','b','replace')`. Check outer status `op`, key, memo miss, forced-refresh flag, context, cache, and value without adding private get/peek/set fields. Call a hit and show that it skips the callback. Then calculate missing `c = 'CCC'`: assert eviction of `a`, order `c,b`, calculated size 7, and the normal dispose/insert/disposeAfter sequence for that successful operation.
- **Missing-key throw.** Keep another key in a size/TTL-tracked cache; call `memo()` for an absent key and throw a unique non-Error object. Assert identity propagation, no insertion/eviction, unchanged stored state and callback logs, and outer status miss reporting. The missing key must remain absent.
- **Fresh success with TTL policy.** Force-refresh a non-MRU fresh entry successfully with `noUpdateTTL: true`. Run once with `updateAgeOnGet: true` and once with false. At 125 after insertion at 100 with TTL 100, remaining TTL must be 100 and 75 respectively, with the replacement at MRU in both cases. In the true case, let the callback write `options.updateAgeOnGet = false` to exercise the entry-time snapshot, and change `options.noDisposeOnSet` to true to exercise set-option mutation.
- **Stale success matrix.** Seed an entry at 100 with TTL 10 and operate at 111. With `allowStale: false` and `noDeleteOnStaleGet: false`, the callback receives `undefined`, a successful result disposes the stale entry with reason `expire`, and adding the result starts its new TTL even when `noUpdateTTL` is true. Change the callback's get options to the opposite values and assert that this does not change the saved lookup behavior. With `noDeleteOnStaleGet: true`, replacement is a `set` replacement and `noUpdateTTL: true` retains the stale start/TTL. With `allowStale: true` and no force, return the stale value without invoking the callback and honor deletion; with force, pass the stale value to the callback and cache the result.
- **Mutable size policy.** On a successful missing-key memo calculation in a size-tracked cache, change `options.size` to a positive explicit size and `options.ttl` to a new value. Assert those values are used. In an independent successful calculation, change `options.sizeCalculation` and verify the resulting entry size. Keep successful context and outer status checks alongside these cases as appropriate.

Do not add public throws on a stale entry under default stale deletion, on a non-MRU existing entry, or with `updateAgeOnGet: true`. Those produce additional public detection of the deliberately isolated mechanism. This instruction belongs only in this hidden authoring file. The visible requirements remain general, and their uncovered semantics remain general source-review obligations.

## Defective twin

Start from the reference. Make exactly one semantic deviation: move the refreshing-path `#get(k, lookupOptions)` call from after `memoMethod` returns to immediately before the `memoMethod` invocation. Keep the initial `#peek`, lookup snapshot, hit path, documentation, callback arguments, status assignments, set call, and all tests unchanged. There must be only one refresh-path commit lookup in either version.

This twin applies normal read mutations before learning whether the calculation succeeded. It is not a different options bug, a swallowed exception, a fake callback result, or changed public tests. Successful refreshing calls in the public and hidden scenarios have a fixed clock during the callback and do not self-mutate the cache, so this moved operation yields the same final state there.
