# 0240: one independent peer, without peer delegation

Prospective treatment revision, 2026-10-10. No product adoption or efficacy
claim. The stopped 0238 sequence and every native result remain unchanged.

## Observed failure and decision

0238 s02-h-codex-v2 completed its owner, peer and peer-child processes, but a
peer inference was cancelled when its child answered. The native terminal event
contained no token usage. Completed inference counters do not measure that
interrupted request. Whole-run usage is PARTIAL/UNKNOWN and the cell stays STOP;
this is not a parser defect or zero-cost work.

**No overengineering:** the proposed pair needs one independent primary-model
counterexample search. Let that reviewer finish its own review directly. Disable
Codex native multi-agent tools only in the peer CLI, with the supported stable
`-c features.multi_agent=false` setting on fresh and resumed calls. Claude's
Read/Grep/Glob-only peer transport is unchanged. Both guides prohibit native or
independent delegation; the primary implementation owner's capabilities and
child configuration are unchanged. Reject captured peer descendants.

**No workaround / No guesswork:** this changes reviewer capability, not
accounting correctness. It may lose parallel coverage or cost more without the
cheaper child. Owner cancellation and other interrupted requests can still make
usage unknown. Keep every existing identity, evidence, accounting, source,
delivery and STOP gate. Never suppress cancellations, estimate their usage, or
pool the old child-enabled run as equivalent evidence.

## Scope and evidence

New helper, guides, smoke request, adapters, packages, staging and identities live
under 0240. Small adapters reuse the unchanged 0238 runner, builder and stager;
their original hashes and the adapter hashes are recorded. S stays byte-identical;
B and S package payloads must match the prior selected payloads. H/P may differ
only in the peer helper and the explicit no-delegation guide sentence.

The design review at
`../0238/results/single-peer-design-review-v1.md` approved testing, not adoption.
Installed native feature metadata recognizes the setting, but only native
request tool definitions can establish that the peer cannot access delegation
tools. The new smoke must show their absence for fresh and resumed peer calls,
their continued availability to the owner, no peer descendants, source stability,
primary model/max effort, completed answers and complete usage. Read-only shell
capability is not a universal process prohibition; inspect native sessions and
captured commands as well as the catalog.

Reuse 0238 s01-h-claude-v3 narrowly for the unchanged Claude-to-Claude launcher,
Read/Grep/Glob restriction, fresh/resume identity, captures and clean teardown.
It did not execute this new guide/package seal and is not efficacy evidence.
New Codex-to-Codex, Claude-to-Codex and Codex-to-Claude routes need prospective
native validation. A failed smoke stops dispatch for diagnosis; no favorable
reroll. Only passing transport permits a separately registered ordinary-request
comparison against bare A, admitted solo B and same-owner check S.

**Optimized:** do not rerun unchanged product suites or an already established
transport fact. Target adapter/argv/policy tests, exact package and install
bindings, and relevant staged evaluator controls. Do not introduce a scheduler,
another sandbox, or an experimental mailbox-preemption feature.

**Worldclass / Production ready:** shipping a new pair default requires quality
and whole-run cost evidence under ordinary activation. A forced smoke or a
working command is insufficient. Negative or inconclusive evidence can close
this mechanism without adding more prompt text. The previously accepted solo
delivery and import corrections remain independently deliverable.
