## Pre-draw review resolutions and scoring rules

Fable and Opus identified oracle gaps, stale-context gating and undefined failure/
scoring rules before any quality draw. Grok attempted tools and returned no usable
review; retain that failed advisory call. Full-access→read-only native qualification
also passed with one initial shell call and zero review calls; fresh returned UNKNOWN.
The runtime now checks only newly appended turn contexts, not old initial contexts.
Model cache bytes are pinned. S includes native session state, tool/test history and
its cache/context-pressure effects; this is not a pure causal test of author bias.

Primary outcome is oracle-complete product (`passed and scope_pass`): every external CLI case, independent existing
self-test, supplied/added tests and file-scope check must pass. Substantiated HIGH/CRITICAL defects are a separate
secondary result; an oracle-complete product with such a defect is not production-ready. Raw case counts are diagnostic, not requirement percentages.
Report success and error tiers separately; error-tier credit is conditional on the
normal populated success case passing. Fewer errors cannot compensate for no working
listing. Source review supplements, and never rewrites, the frozen oracle score.

Finding adjudication uses neutral product/review labels before the comparison table:
Fable/Opus review claims against request and source; root verifies a concrete
counterexample for each substantiated defect. A closure needs the same counterexample
to fail on initial and pass on repair. Record unsupported/unreproduced findings and
any complete→incomplete harm. Supplemental finding probes stay separately labelled;
they do not add retrospective primary cases. The outer owner knows orchestration
identities, so this is reviewer blinding, not a fully blinded research organization.

The prediction is supported descriptively only if F has more distinct substantiated
initial omissions AND more incomplete→complete products, with no greater harm.
Report split outcomes separately. If initials all pass, report no observed repair
headroom; do not treat that as evidence of review equivalence. One repair draw per
review includes repair sampling noise. No no-review-repair arm exists here.

An observed native budget exit124 after thread start, an empty answer, invalid findings
or attempted review tool use is a retained scheduled model outcome. Repairs still run
on the sealed available product and verbatim review. An arm with a review tool attempt
is fidelity-ineligible, not a successful no-tool comparison. A124 with native error events is transport-suspect and stops for inspection.
Other nonzero exits,
missing thread/sandbox evidence, auth errors or nonquiescence stop as infrastructure
failures; never infer a quality verdict or automatically retry. Completed seals may
be resumed unchanged. An interrupted in-progress stage requires explicit evidence
inspection; no stage is rerolled and no initial/session directory is deleted to restart.

Audit actual command/patch streams for access outside each assigned product (executables,
required test fixtures and native auth excluded). Reference/oracle/sibling access makes
that arm contaminated and ineligible; the full-access worker boundary is instructional,
not a filesystem sandbox. Record review packet hash equality, actual context/model/
effort, native input/cache usage, observable compaction events and whether a review
cites prior-only knowledge. A compacted S is reported as resumed summarized history;
no hidden server-side history preservation is certified by the nonce probe.

The calibration alternative only changes the size primitive; it is not an independent
reference. Missing coverage beyond the registered cases remains a limitation. Existing
self-test preservation is checked independently on disposable copies after sealing
all products, so participant-authored tests cannot alter sealed evidence. Original
and negative calibration controls are not native efficacy draws.
