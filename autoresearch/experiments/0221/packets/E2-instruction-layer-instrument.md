## Summary

One session builds and runs an isolated instrument that compares the always-loaded instruction layer (the installed CLAUDE.md/AGENTS.md managed block) in three arms: current (installer render of the base-SHA files), slim (a deletion-only subset chosen with the DECISIONS.md:195 / 0069.3 categories, keeping the user-directed principles block) and none. It runs on claude-opus-5-5, claude-sonnet-5, gpt-6-astra and gpt-6-sol. The runner as it stands cannot do this. It is Claude-only, and it leaks the user's global ~/.claude/CLAUDE.md, because `--setting-sources project,local` does not exclude it (0068:445-448). It also copies an untracked skills dump, has no way to run a no-instructions arm, counts a launcher failure as a violation, and does not confirm which model actually ran. The 0182 Codex launcher is untracked, runs only astra, and its frozen model catalog lacks gpt-6-sol. The fix reuses the sealed claude-isolation.py launcher, moves 0182's AGENTS render check into the same runner, and adds variant and probe options to the matrix driver. Two legs are scored with existing mechanical oracles: the 6-probe drift-bait panel for discipline (N=4) and 8 EQ3 hidden-oracle tasks for completion (N=2). That is 40 runs per model × variant, 480 in total, about 8 hours with a Claude lane and a Codex lane running in parallel. Token usage is recorded but never capped, and a frozen adjudicate.py decides the outcome. The PR touches only benchmark/probes, two docs, a new iteration and experiment directory, and deletes the superseded April proposal. CLAUDE.md, AGENTS.md, bin/, lint, CI, config/skills and .agents are not changed; adopting slim is a follow-up that depends on the result. Delivery is push + PR only.
