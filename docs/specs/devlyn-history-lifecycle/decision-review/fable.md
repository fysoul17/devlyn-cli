## Decisions

**D1 — AMEND.**

*Strongest form.* Task terminal is the only event that means "no longer needed"; count and age are proxies that both over- and under-delete. The accepted run already survives byte-verified in custody, and NEEDS_WORK adjudications are committed as spec amendments per the outer loop, so run archives hold nothing the durable artifacts lack. An archived incomplete run is provably dead: `resolve-bootstrap.py:213-218` refuses to continue an unfinished prior run and only reads top-level state. I searched `SKILL.md` for resume, unfinished, prior run and interrupted and found no continuation path.

*Strongest counter.* Two concrete breakages. First, ordering: on resume, `task-complete.py:300-302` and `:529-532` re-verify the accepted run's files in the worktree. Deleting at the first "merged" signal, before cleanup finishes, makes every resume fail with "evidence bytes changed" and the task never reaches COMPLETE. Second, identification: no field links the other iterations to the accepted run id. In-place completion shares one `.devlyn` across tasks on that checkout. If task A completes while task B's NEEDS_WORK archive sits in the same `runs/`, "delete everything except the accepted run" wipes B's findings and B re-enters without them.

*Decisive criterion.* Whether any consumer needs a run after the receipt reaches a terminal status, and whether the task's run set can be named exactly. Consumers are resume, which needs the files until COMPLETE, custody, which has its own copy, and the devlyn-os badge, which degrades to "not verified" at `work_monitor.rs:2054-2058`.

*Synthesis.* Owner: the outer owner via `task-complete.py`, never resolve. Trigger: receipt status COMPLETE, after custody verification at `:519-520` and, for linked trees, before the ignored-content check at `:535-536`, which today refuses removal when unaccepted iteration files remain. Deleted: every `runs/rs-*` whose `base_ref.branch` equals the receipt's branch, plus `.devlyn/acceptance.json` and `.devlyn/checks.log`. Retained: any run whose id matches a live top-level `pipeline.state.json`, anything not `rs-` prefixed, custody. Safety: refuse if a symlink appears in the path chain; rename each directory to `<id>.deleting-<receipt>` first, then remove, so a crash leaves a tombstone that is removable unconditionally on retry. Failure surfaces as `CLEANUP_PENDING` with the retry command, never silence, and the product verdict is unchanged.

**D2 — AMEND.**

*Strongest form.* An artifact born without an owner has no terminal event, so it can never be cleaned without guessing, and `task-completion.md:130` forbids guessing. Ownership at creation is the only mistake-free design, and the owned scratch already exists and is already cleaned.

*Strongest counter.* The contract itself manufactures these files. `CLAUDE.md` demands a written prediction before every experiment, and `task-completion.md:29-31` says to keep reports and restart evidence outside scratch without saying where. The pyx-memory sample shows exactly that output: PREDICTION, REPORT and HANDOFF-before files under dated `x50-*` directories. Forbidding creation without naming a home recreates them elsewhere. Worse, some of them are live cross-task state: `HANDOFF.md:3` points the next session at `.devlyn/NEXT-SESSION-routing-boundary.md`, and `:110` parks intentional WIP under `.devlyn/0151/`. A one-time sweep kills the program's continuation, and moving those into a task-owned location deletes them with that task while later tasks still cite them. Enforcement is also absent: `state-schema.md:69` exempts `.devlyn/` from the untracked-baseline gate, and the finish gate reads only the plan surface.

*Decisive criterion.* Every artifact must be born with exactly one of two lifetimes, task-bound or durable, and the rule must be checked by a script, not prose.

*Synthesis.* Owner: `task-complete.py` at allocate and complete, plus the finish gate. Rule: `.devlyn` top level admits only an allowlist, namely the CLI per-run set in `PER_RUN_PATTERNS`, `runs/`, `process-evidence/`, `probes/`, `engines.json`, `acceptance.json`, `checks.log`, and the devlyn-os entries `worktrees/`, `tasks/`, `locks/`, `index.db`, `observed-sessions/`, `suggestions/`, `ops-held/`, `queue-drains/`, `queue-decisions/`, `storage-policy.json`, `storage-cleanup.json`. Task-bound evidence goes to the receipt scratch. Durable evidence is committed under `docs/specs/<id>/` or `autoresearch/`. Any other top-level entry makes completion report `UNOWNED_ARTIFACTS` with the list, and the task is never described as cleaned. Nothing is deleted by the check. The one-time cleanup is a triage with a printed plan that marks the routing pointer and parked WIP as retained before anything is removed.

**D3 — AMEND.**

*Strongest form.* Opt-in prospective enrollment guarantees the incident recurs. The sample shows no `storage.json` and no `keep` marker anywhere, so every existing terminal run is "historical" and only a manual preview can ever name it. Terminal spools are PTY replay with no reader after exit. Default-on, age-based, whole-folder removal with the existing guard, keep and dismissed protections is the smallest rule that bounds the data.

*Strongest counter.* Three concrete failures. First, the crashed class: a session killed by ENOSPC, force-quit or power loss has no exit record, so `work_monitor.rs:1274` excludes it forever. The incident's own aborted session is likely in this class, and D3 as coded would never touch it. Second, whole-folder removal reverses three approved lines of the user's own spec: `spec.md:23` keeps the record with details unavailable, `:26` never silently enrolls historical files, `:27` says never recursively delete a run directory. It also deletes `usage/` sidecars, the settled cost evidence per `run_dir.rs:67-78`. Third, the lock file lives inside the directory being removed. A new writer opening `guard.lock` after unlink gets a fresh inode and a lock that no longer excludes the cleaner, so an orchestrator seat resumed during deletion races it.

*Decisive criterion.* Whether any reader needs the folder after exit plus the window. Orchestrator resume is the only one, and `open_terminal.rs:657-664` restricts resume to orchestrator seats, which `work_monitor.rs:1276-1280` already protects until dismissed.

*Synthesis.* Owner: the desktop work monitor, app-lifetime timer in Rust over every known workspace, not the renderer view. Policy default: on, 30 days. Delete the enrollment record, both cleanup modes and the historical preview; one policy applies at cleanup time. Eligible: `open_*` and `terminal_*` runs that are not keep-pinned, not orchestrator-undismissed, not in a running, suspended or merge_ready loop state, and ended. Ended means an exit record exists, or the last pid is dead and the exclusive guard is acquired, with the exit time taken as the snapshot mtime. Age is measured from that time. Operation: under the exclusive guard, refuse any symlinked component as `:1189-1214` does, rename the directory to a tombstone, then remove; record each removal in `storage-cleanup.json` since no in-folder receipt can survive. Record the spec reversal as an amendment with the named delta above.

## Cross-cutting, missing decisions, drift

**Namespace ownership.** `.devlyn/runs/` is partitioned by prefix today only by accident: `rs-*` for the CLI, `open_*` and `terminal_*` for devlyn-os, `run_*` for devlynd loops. Write that partition into both repos and make each cleaner delete only its own prefix, never "everything not mine". The 42 incomplete `rs-*` archives are dead data, so the smallest fix is widening prune eligibility to archived incomplete runs that hold no bootstrap residue; that is a fallback for runs with no task, not the primary mechanism the user rejected. The 29 legacy directories and any `run_*` leftovers get deleted once in migration. Migration itself: quit devlyn-os, confirm no bootstrap lock, print a per-entry plan with class and action, retain live-guard runs, undismissed orchestrator runs, `worktrees/`, `tasks/`, `locks/`, the routing pointer and parked WIP, then rename-and-remove with a written receipt. Never `rm -rf .devlyn`.

**Missing decisions**:

1. Is LOCAL_ONLY terminal for run deletion? The helper retains the workspace and resume path, so I recommend no.
2. Custody expiry. The accepted run is duplicated under `.git/devlyn-completion/` with no expiry per `task-completion.md:139`. Deleting the run but not custody frees nothing for that run.
3. Task-to-run key: stamp the receipt id into `pipeline.state.json` at bootstrap, or match `base_ref.branch` and accept branch-name reuse collisions.
4. The durable home for cross-task program evidence, without which D2 cannot be enforced.
5. Whether pid-dead plus guard-free counts as exit evidence for crashed sessions.
6. Whether History rows and `usage/` records may vanish with the folder.
7. Where the automatic tick lives and whether it covers unopened workspaces.

**Out-of-scope drift I leave out**: a stdout spool size cap, which bounds live growth rather than finished history; spool compression; a cross-repo sweeper CLI; moving `.devlyn` to a cache directory; making the CLI read the devlyn-os policy.
